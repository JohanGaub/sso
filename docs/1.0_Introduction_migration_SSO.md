# 1. Introdcution à la migration SSO

Cette section regroupe les guides d'exécution de la migration SSO. Choisissez **un seul** parcours selon le protocole et le mode de gestion, puis déroulez son tableau de suivi.

---

## Règle de routage

Choisissez votre guide selon le protocole et, pour l'OIDC, le mode de gestion.

> [!NOTE]
> **Rappel :** il n'existe **pas** de parcours **SAML – gestion managée**. Le SAML n'est proposé qu'en **gestion privée**.

| Protocole | Mode | Guide | Décisions clés à prévoir |
| --- | --- | --- | --- |
| OIDC | Gestion managée (claims uniquement) | **1.1** Guide migration OIDC - Gestion managée (hébergement Cloud Place avec module Apache) | — |
| OIDC | Gestion privée (flux + claims) | **1.2** Guide migration OIDC - Gestion privée (hébergement DataCenter ZCI, Cloud Public et Cloud Place sans module Apache) | **Avec ou sans PKCE** : **avec PKCE** si SPA / app mobile (pas de backend pour stocker un secret) ; **sans PKCE** possible si l'application a un backend serveur (Symfony, Spring, etc.). Détail dans le guide **1.2**. |
| SAML | Gestion privée **(seul mode)** | **1.3** Guide migration SAML - Gestion privée (hébergement DataCenter ZCI, Cloud Public et Cloud Place sans module Apache) | Checklist IAM : **3.4** |

---

## Documents de cette section

- **1.1 Guide migration OIDC - Gestion managée** — flux OIDC géré par Apache (pas de code OIDC dans l'appli) ; claims lus via `OIDC_CLAIM_*`.
- **1.2 Guide migration OIDC - Gestion privée** — flux Authorization Code (avec ou sans PKCE) implémenté dans l'appli ; claims lus dans l'ID Token / UserInfo.
- **1.3 Guide migration SAML - Gestion privée** — flux SAML (SP/IdP-initiated) implémenté dans l'appli ; attributs lus dans l'Assertion.
