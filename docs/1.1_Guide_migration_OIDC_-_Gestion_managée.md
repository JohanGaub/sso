# 1.1 Guide migration OIDC - Gestion managée

En gestion managée :

- Le CAM Eagles fournit la **fiche de renseignement** à l'équipe IAM avec les informations pour configurer Entra ID (URL du site, redirect URIs, claims nécessaires).
- L'équipe IAM configure Entra ID (interface dédiée), ce qui génère le ClientID et le ClientSecret, puis les transmet via le CAM Eagles à l'équipe Gestion managée.
- L'équipe Gestion managée reçoit le Client ID / Client Secret et configure la mécanique OIDC.
- L'équipe applicative et/ou l'équipe de raccordement adapte la lecture des **claims** dans le code.

> [!NOTE]
> **NB :** en gestion managée, les claims sont injectés par le module Apache (préfixe `OIDC_CLAIM_*`) — voir **4. Où lire les claims** et **5. Exemples de code**.

## 3. Pièges courants

- **Compte non habilité** : tester avec un compte non habilité et conclure à un problème OIDC alors que c'est un problème de droits applicatifs.
- **Préfixe `OIDC_CLAIM_` vs `REDIRECT_OIDC_CLAIM_`** : selon que l'application est appelée directement ou après redirection interne, le préfixe change. Si un claim attendu est vide, tester les deux préfixes (voir **3.1 Correspondance des claims OIDC**).
- **Claim absent côté Apache** : le claim n'apparaît pas dans les variables d'environnement parce qu'il n'a pas été demandé dans la **fiche de renseignement** ou n'est pas exposé par Entra ID. Vérifier la liste transmise à l'équipe IAM avant de modifier le code.
- **Cache navigateur / session legacy** : après la bascule, l'utilisateur reste connecté via un cookie Gardian résiduel. Forcer une suppression des cookies du domaine pour reproduire un parcours OIDC propre.
- **Casse du nom de claim** : `OIDC_CLAIM_email` vs `OIDC_CLAIM_Email` — la casse peut varier selon la configuration Apache. Lister une fois les clés `OIDC_CLAIM_*` présentes dans l'environnement (`$_SERVER` en PHP) avant de coder.

## 4. Où lire les claims

En **gestion managée**, le module Apache (`mod_auth_openidc`) gère le flux OIDC : redirection, échange de tokens, validation. Votre application **ne code pas** le flux OIDC ; elle lit les **claims** que Apache injecte dans les **variables d'environnement** de la requête HTTP.

> **Règle simple :**
>
> - Préfixe le plus courant : `OIDC_CLAIM_NOM` (remplacer NOM par le nom du claim ; ex. `OIDC_CLAIM_email`, `OIDC_CLAIM_nom`, `OIDC_CLAIM_role`).
> - Si l'application passe par une redirection interne : préfixe `REDIRECT_OIDC_CLAIM_NOM` (même logique, autre préfixe).
> - Correspondance Legacy ↔ Entra ID : document **3.1 Correspondance des claims OIDC**.

**En cas de claim manquant :**

1. Vérifier que le claim est listé dans la **fiche de renseignement** transmise à l'IAM.
2. Lister les variables `OIDC_CLAIM_*` effectivement présentes (log temporaire des clés d'environnement).
3. Consulter **3. Pièges courants** (préfixe, casse, cache).

## 5. Exemples de code

Les exemples ci-dessous supposent que le claim `email` est exposé sous `OIDC_CLAIM_email`. Adaptez le nom du claim et le préfixe selon votre application (voir **3.1 Correspondance des claims OIDC**).

### Symfony (PHP)

```php
// Claims injectés par Apache (mod_auth_openidc) — Request Symfony
$email = $request->server->get('OIDC_CLAIM_email');
$nom = $request->server->get('OIDC_CLAIM_nom');
$role = $request->server->get('OIDC_CLAIM_role');
// Équivalent PHP natif : $_SERVER['OIDC_CLAIM_email'], etc.
if ($role !== null && !in_array($role, ['admin', 'user'], true)) {
    throw new AccessDeniedException('Rôle non autorisé');
}
```

### CodeIgniter (PHP)

```php
// Variables d'environnement injectées par Apache
$email = $_SERVER['OIDC_CLAIM_email'] ?? null;
$nom = $_SERVER['OIDC_CLAIM_nom'] ?? null;
$role = $_SERVER['OIDC_CLAIM_role'] ?? null;
```

### Python (ex. Flask / Django)

```python
# Flask : request.environ ; Django : request.META
email = request.environ.get('OIDC_CLAIM_email')  # Flask
# email = request.META.get('OIDC_CLAIM_email')  # Django
nom = request.environ.get('OIDC_CLAIM_nom')
role = request.environ.get('OIDC_CLAIM_role')
```

### TypeScript (Node.js, backend — ex. Express / Nest)

```javascript
// Apache transmet souvent les claims en en-têtes HTTP (casse normalisée)
const email = req.headers['oidc-claim-email'];
const nom = req.headers['oidc-claim-nom'];
const role = req.headers['oidc-claim-role'];
```
